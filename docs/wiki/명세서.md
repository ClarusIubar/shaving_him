## 1. 1D Uint8Array 비트맵 메모리 모델

### 1.1. 설계 목적
수염 매트릭스는 $280 \times 219 = 61,320$개의 격자 셀로 구성됩니다. 2차원 객체 배열(`Array<Array<{hasHair: boolean}>>`) 사용 시 수십만 개의 힙 객체와 포인터 오버헤드가 발생하여 면도 시 극심한 가비지 컬렉션(GC Pause)이 발생합니다.

### 1.2. 메모리 구조 및 수식
- **버퍼 크기**: $\text{Buffer Size} = \text{rows} \times \text{cols} = 61,320 \text{ Bytes} \approx 60 \text{ KB}$
- **인덱스 매핑 공식**:
  $$\text{Index}(r, c) = r \times \text{cols} + c$$
- **상태 값**:
  - `0`: 수염 없음 (피부 노출)
  - `1`: 수염 존재 (깎아야 할 대상)

### 1.3. 무할당(Zero Allocation) 면도 연산
```javascript
shave(r, c, radius = 1) {
    let count = 0;
    const dirtyCells = [];
    const startR = Math.max(0, r - radius);
    const endR = Math.min(this.rows - 1, r + radius);
    const startC = Math.max(0, c - radius);
    const endC = Math.min(this.cols - 1, c + radius);

    for (let row = startR; row <= endR; row++) {
        const rowOffset = row * this.cols;
        for (let col = startC; col <= endC; col++) {
            const idx = rowOffset + col;
            if (this.data[idx] === 1) {
                this.data[idx] = 0; // In-place O(1) 비트 반전
                count++;
                dirtyCells.push({ r: row, c: col });
            }
        }
    }
    this.remainingHairs -= count;
    return { count, dirtyCells };
}
```

## 2. 1-Photo 인브라우저 4단계 아스키 생성 알고리즘

```text
[입력 이미지 (File / Element)]
        │
        ▼ (Stage 1: 캔버스 리사이징)
[ImageData 픽셀 버퍼 (280x219, RGBA)]
        │
        ▼ (Stage 2: 표준 휘도 그레이스케일)
[Luminance Y Matrix (0~255)]
        │
        ├─────────────────────────────┐
        ▼ (Stage 3: 10단계 램프)        ▼ (Stage 4: 피부톤 임계 분리)
[textGrid: string[]]          [hairPositions: Array<{r, c}>]
```

1. **휘도 계산식 (ITU-R BT.601)**:
   $$Y = 0.299 \times R + 0.587 \times G + 0.114 \times B$$
2. **아스키 램프 매핑**:
   - 10단계 밀도 램프: `RAMP = " .:-=+*#%@"`
   - 글리프 인덱스 계산 공식:
   $$\text{charIndex} = \left\lfloor \frac{255 - Y}{255} \times (\text{length}(\text{RAMP}) - 1) \right\rfloor$$
3. **피부-수염 델타 마스킹**:
   - $Y > 120$: 밝은 피부 영역 ➔ 수염 제외
   - $Y \le 120$: 어두운 수염/눈/윤곽 영역 ➔ `hairPositions` 등록

## 3. 브레젠험 8-연결 선분 래스터라이저 사양

- **수학적 불변성**: 시작점 $(r_0, c_0)$에서 끝점 $(r_1, c_1)$까지의 보간 점들은 인접 점 간 체비쇼프 거리(Chebyshev Distance)가 정확히 $1$ 이하를 만족해야 합니다.
  $$\max(|r_{i+1} - r_i|, |c_{i+1} - c_i|) \le 1$$
- **총 점수 길이**:
  $$L = \max(|r_1 - r_0|, |c_1 - c_0|) + 1$$

## 4. High-DPI 정규화 및 GPU 하드웨어 가속 사양

### 4.1. 레티나/모바일 좌표 정규화
화면 비율이나 DPR(Device Pixel Ratio)에 무관하게 캔버스의 상대 비율(Normalized Ratio)을 통해 정확한 그리드 좌표를 계산합니다:
$$\text{normX} = \frac{\text{clientX} - \text{rect.left}}{\text{rect.width}}, \quad \text{col} = \lfloor \text{normX} \times \text{cols} \rfloor$$
$$\text{normY} = \frac{\text{clientY} - \text{rect.top}}{\text{rect.height}}, \quad \text{row} = \lfloor \text{normY} \times \text{rows} \rfloor$$

### 4.2. GPU `translate3d` 커서 컴포지팅
DOM Reflow를 완전히 차단하기 위해 `transform: translate3d(...)`를 사용합니다:
```javascript
cursor.style.transform = `translate3d(${clientX}px, ${clientY}px, 0) translate(-50%, -50%) rotate(-30deg)`;
```

## 5. Web Audio API 절차적 실시간 음향 합성 사양

### 5.1. 면도 마찰음 (Razor Friction Noise)
- **노이즈 소스**: 50ms 길이의 실시간 생성 White Noise 버퍼 ($-1.0 \sim 1.0$ 균등 난수).
- **대역통과 필터 (BiquadFilter)**:
  - `type`: `bandpass`
  - `frequency`: $2,200 \text{ Hz}$
  - `Q`: $3.0$
- **게인 엔벨로프 (Gain Envelope)**:
  - 초기 게인: $0.12$
  - 감쇄: $0.04$초 내에 $0.001$로 지수형 감쇄 (`exponentialRampToValueAtTime`).

### 5.2. 콤보 차임벨 (Harmonic Combo Chimes)
- **발진기**: `sine` 웨이브.
- **주파수 공식**:
  $$f_{\text{combo}} = 523.25 \text{ Hz (C5)} + \min(\text{comboCount} \times 45, 600) \text{ Hz}$$
- **엔벨로프**: $0.12$초 감쇄.

### 5.3. 올클리어 승리 팡파레 (Victory Fanfare)
- **발진기**: `triangle` 웨이브.
- **화음 4음계**: $523.25\text{Hz (C5)} \rightarrow 659.25\text{Hz (E5)} \rightarrow 783.99\text{Hz (G5)} \rightarrow 1046.50\text{Hz (C6)}$.
- **시차 재생**: $0.1$초 간격 시차 트리거 및 $0.25$초 릴리즈 엔벨로프.

## 6. 런타임 스키마 무결성 검증 사양

모든 DTO는 런타임에 [`src/domain/schema-validator.js`](file:///d:/Code305/shaving_him/src/domain/schema-validator.js)를 통해 검증되며, 비정상 데이터 주입 시 즉시 예외를 발생시켜 시스템 오염을 차단합니다.
- `validateStageData`: 행/열의 자연수 여부, 수염 좌표의 그리드 범위 초과 여부, 텍스트 그리드 규격 검증.
- `validateSnapshot`: 점수/시간의 유한수(Finite) 여부, 콤보 카운트 및 퍼센티지 범위 검증.
